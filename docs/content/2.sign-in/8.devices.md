For apps on devices without a browser or keyboard: a TV, a console, a CLI, a desktop app. The device shows "Go to
example.com/device and enter ABCD-1234", and the person approves it from their phone or computer.

It's Better Auth's [Device Authorization plugin](https://better-auth.com/docs/plugins/device-authorization), the
OAuth device grant (RFC 8628).

## Turning it on

::steps{level="3"}

### Enable it, and list your apps

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  betterAuthUi: {
    deviceAuthorization: {
      enabled: true,
      // The apps allowed to ask, by client_id, with the name the page shows.
      clients: {
        'tv-app': 'Our TV app',
        'our-cli': 'Our CLI'
      }
    }
  }
})
```

### Run Better Auth's migrations

The plugin adds a `deviceCode` table.

::

::warning
Without `clients`, any client id is accepted (Better Auth's default) and the page shows the raw id. The module warns
at build time: set it in production.
::

## The approval page

`/device` is for signed-in people; others sign in first and come back with their code. It:

1. takes the code, or reads it from `?user_code=` when the device shows a link;
2. shows which app is asking, and what access it wants;
3. warns not to approve a code someone else sent;
4. approves or denies it.

Approvals are recorded in the [audit log](/admin/audit-log). The signed-in device shows on the account page's Devices
tab, where it can be signed out.

## The device side

Asking for a code and waiting for approval is your app's job, with Better Auth's `deviceAuthorizationClient`:

```ts
const { data } = await authClient.device.code({ client_id: 'tv-app' })
// Show data.user_code and data.verification_uri, then every `interval` seconds:
const { data: token } = await authClient.device.token({
  grant_type: 'urn:ietf:params:oauth:grant-type:device_code',
  device_code: data.device_code,
  client_id: 'tv-app'
})
```

Once approved, that returns a Better Auth session token, used with the [Bearer plugin](/integrations/tokens#bearer-tokens).
See Better Auth's [device authorization docs](https://better-auth.com/docs/plugins/device-authorization) for the
full flow.

## Options

::field-group
  ::field{name="enabled" type="boolean" default="false"}
  ::

  ::field{name="clients" type="Record<string, string>"}
  The apps allowed to ask, by `client_id`, with the name the page shows for each.
  ::

  ::field{name="page" type="string" default="'/device'"}
  The approval page's path, which Better Auth gives devices as `verification_uri`.
  ::

  ::field{name="expiresIn" type="string" default="'30m'"}
  How long a code lasts.
  ::

  ::field{name="interval" type="string" default="'5s'"}
  How often devices may check whether they're approved.
  ::

  ::field{name="userCodeLength" type="number" default="8"}
  Characters in the code people type.
  ::
::

Better Auth's [Passkey plugin](https://better-auth.com/docs/plugins/passkey).

## Turning it on

::steps{level="3"}

### Install the plugin's package

```bash [Terminal]
pnpm add @better-auth/passkey
```

### Enable it

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  betterAuthUi: {
    passkey: { enabled: true }
  }
})
```

### Run Better Auth's migrations

The plugin adds a `passkey` table.

::

## How people use it

- **Account page:** add a passkey, optionally named ("Work laptop"); the browser asks where to keep it. People see when
  each was added and whether it's synced, and can rename or remove them.
- **Sign-in page:** a "Passkey" button. The browser also offers saved passkeys straight from the email field, where it
  supports that. Either way, people go on to where they were heading.
- **No two-factor code:** a passkey is already two factors, so passkey sign-ins aren't asked for one.

## Options

All optional; Better Auth's defaults otherwise.

::field-group
  ::field{name="enabled" type="boolean" default="false"}
  ::

  ::field{name="rpName" type="string"}
  The site name passkey prompts show. Defaults to your Better Auth `appName`.
  ::

  ::field{name="rpID" type="string"}
  The domain passkeys belong to, for example `example.com`. Defaults to your base URL's hostname.
  ::

  ::field{name="origin" type="string"}
  Where passkeys are used from, for example `https://example.com`. Defaults to the request's origin.
  ::
::

::warning
Passkeys belong to a domain. Set `rpID` before people start adding them: passkeys made for one domain don't work on
another.
::

## In the admin

Staff can remove a user's passkey from their page, for example when a device is lost. See
[Managing users](/admin/users#lost-a-device).

## Adding the plugin yourself

Leave `passkey.enabled` off, add `passkey()` and `passkeyClient()` to your auth configs, and the pages pick it up.

## Captcha

Bot protection with Better Auth's [Captcha plugin](https://better-auth.com/docs/plugins/captcha): a Cloudflare
Turnstile, hCaptcha or reCAPTCHA v2 widget on the forms it guards. Better Auth checks the answer on its server.

::steps{level="3"}

### Add your site key

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  betterAuthUi: {
    captcha: {
      provider: 'cloudflare-turnstile', // or 'hcaptcha', 'google-recaptcha'
      siteKey: '0x4AAA…'
    }
  }
})
```

### Set the secret key in the environment

```bash [.env]
BETTER_AUTH_CAPTCHA_SECRET_KEY=0x4AAA…
```

It's read at runtime, never from `nuxt.config.ts`.

::

### Which forms it guards

By default, the forms that can create an account or send something:

- signing up (`/sign-up/email`);
- asking for a [sign-in link](/sign-in/methods#sign-in-links) (`/sign-in/magic-link`);
- asking for a [code by email](/sign-in/methods#codes-by-email) (`/email-otp/send-verification-otp`);
- asking for a [code by text](/sign-in/phone-numbers) (`/phone-number/send-otp`).

Choose your own with `endpoints`, for example to guard signing in and password resets as well:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  betterAuthUi: {
    captcha: {
      provider: 'cloudflare-turnstile',
      siteKey: '0x4AAA…',
      endpoints: ['/sign-up/email', '/sign-in/email', '/request-password-reset']
    }
  }
})
```

The widget is loaded in the browser only.

## Breached passwords

With `haveIBeenPwned: true`, Better Auth's Have I Been Pwned plugin refuses passwords found in data breaches, at
sign-up, password changes and resets. The forms say the password will be checked.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  betterAuthUi: {
    haveIBeenPwned: true
  }
})
```

::note
Only the first 5 characters of the password's SHA-1 hash leave your server.
::

## Security alerts

Emails to an account's owner when something sensitive happens to it, each with a link to where they can act. They go
through the module's [emails](/customization/emails), so `emails.send` must be set.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  betterAuthUi: {
    // All of them:
    securityAlerts: true,
    // Or pick:
    // securityAlerts: { newSignIn: true, passwordChanged: true }
  }
})
```

| Alert | Template | Sent when |
| --- | --- | --- |
| `newSignIn` | `new-sign-in` | Someone signs in from a browser and OS the account hasn't used before |
| `passwordChanged` | `password-changed` | The password is changed, reset, set for the first time, or set by an admin |
| `twoFactor` | `two-factor-changed` | Two-factor is turned on or off, including by an admin |
| `passkeyAdded` | `passkey-added` | A passkey is added |

- **"A device the account hasn't used before"** compares the browser and OS ("Chrome on Windows") with the account's
  other sessions and, with the audit log on, its last 100 sign-ins. It's a hint, not a fingerprint: a second Windows
  PC with Chrome counts as known.
- **No alerts** in an account's first two minutes (signing up signs in), when an admin impersonates someone, or to
  guests.
- **With two-factor on**, the sign-in alert comes after the code, when the sign-in really completes.
- Times are written in UTC, in the emails' language.

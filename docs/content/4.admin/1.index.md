The admin dashboard is on by default, at `/admin`. Staff manage users there through Better Auth's
[Admin plugin](https://better-auth.com/docs/plugins/admin), which the module adds for you. Everything in it is backed
by Better Auth: it checks every action's permission on its server.

## Getting in

Only signed-in staff can open it: users with the admin role, and [roles](/admin/roles) that can list users. Others are
sent to the sign-in page, or get a 403.

Nobody has the admin role at first. Give it to yourself once in the database:

```sql
update user set role = 'admin' where email = 'you@example.com';
```

After that, admins can give the role to others from the dashboard.

## Finding your way

The layout comes from the [Nuxt UI dashboard template](https://github.com/nuxt-ui-templates/dashboard): a collapsible
sidebar headed by your app's name (Better Auth's `appName`), and a menu at its foot with your account, light, dark or
system appearance, the way back to your site, and signing out.

**Search** (:kbd{value="meta"} :kbd{value="K"}) finds pages, actions such as "Create a user", and users by name or
email.

| Shortcut | Goes to |
| --- | --- |
| :kbd{value="G"} then :kbd{value="H"} | Home |
| :kbd{value="G"} then :kbd{value="U"} | Users |
| :kbd{value="G"} then :kbd{value="S"} | Sessions |
| :kbd{value="G"} then :kbd{value="A"} | Audit log |
| :kbd{value="G"} then :kbd{value="C"} | Configuration |

## The pages

### Home

Total users, sign-ups compared with the previous period, active sessions and bans; a sign-ups chart by day, week or
month over a range you choose; and the newest users. With [activity tracking](/admin/audit-log#last-active-and-online-now),
an "Online now" card too.

### Users

Everyone, with search, filters and actions. See [Managing users](/admin/users).

### Sessions

Everyone signed in, most recently active first, with device, IP, when they signed in and when the session expires.
Sign any session out. It needs the `session: list` permission.

::note
"Last active" here is when Better Auth last refreshed the session, which is at most daily by default. The page isn't
available when sessions live only in secondary storage such as Redis.
::

### Organizations and single sign-on

With [organizations](/organizations) and [single sign-on](/organizations/sso) on, pages listing every organization and
every identity provider.

### Audit log

Every admin action and, by default, users' own sign-ins. See [Audit log and activity](/admin/audit-log).

### Configuration page

How your app is set up, read-only: sign-in methods and providers, email verification and password rules, two-factor
(and who must use it), passkeys, impersonation, email changes and deletion, which emails have your own template, the
audit log, activity tracking and every integration.

It also has a **roles and permissions** table: every Better Auth Admin permission against every role, checked exactly
as the server checks it, with the roles that can open the admin marked "Staff".

## Options

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  betterAuthUi: {
    admin: {
      route: '/admin',
      impersonation: true,
      notes: true
    }
  }
})
```

::field-group
  ::field{name="enabled" type="boolean" default="true"}
  The admin dashboard. Off, none of its pages, routes or Better Auth plugins are added.
  ::

  ::field{name="route" type="string" default="'/admin'"}
  Where the admin pages live.
  ::

  ::field{name="role" type="string" default="'admin'"}
  The role that can do everything.
  ::

  ::field{name="roles" type="object" default="{}"}
  More staff roles, with the permissions each has. See [Staff roles](/admin/roles).
  ::

  ::field{name="impersonation" type="boolean" default="false"}
  Let admins sign in as a user. See [Signing in as a user](/admin/users#signing-in-as-a-user).
  ::

  ::field{name="notes" type="boolean" default="false"}
  Private staff notes on each user's page. See [Staff notes](/admin/users#staff-notes).
  ::

  ::field{name="auditLog" type="boolean" default="true"}
  Record admin actions. See [Audit log and activity](/admin/audit-log).
  ::

  ::field{name="auditLogRetentionDays" type="number" default="30"}
  Days the audit log keeps entries. `0` keeps them forever.
  ::

  ::field{name="auditUserEvents" type="boolean" default="true"}
  Also record users' sign-ins, failed sign-ins, sign-outs and password changes.
  ::

  ::field{name="activityTracking" type="object" default="{ enabled: false }"}
  "Last active" and "Online now". `{ enabled: true, updateInterval: 300000 }`.
  ::
::

### Better Auth Admin plugin options

Passed through to Better Auth as [documented](https://better-auth.com/docs/plugins/admin#options). All optional.

::field-group
  ::field{name="defaultRole" type="string" default="'user'"}
  The role new users get: `user`, the admin role, or one of `roles`.
  ::

  ::field{name="defaultBanReason" type="string" default="'No reason'"}
  The ban reason when an admin gives none.
  ::

  ::field{name="defaultBanExpiresIn" type="number"}
  Seconds a ban lasts when an admin gives no length. Forever by default.
  ::

  ::field{name="bannedUserMessage" type="string"}
  What banned users see when they try to sign in.
  ::

  ::field{name="impersonationSessionDuration" type="number" default="3600"}
  Seconds an impersonation session lasts.
  ::
::

::note
The Admin plugin adds `role`, `banned`, `banReason` and `banExpires` to the user table, and `impersonatedBy` to
sessions: run Better Auth's migrations after installing.
::

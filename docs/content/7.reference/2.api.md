Composables, components and server utilities are auto-imported. The rest come from the package's entries.

## Composables

### `useAuthActiveOrganization()`

The signed-in user's active organization, server-rendered. It follows the session, so switching organizations
updates it. Only with `organization` on. [More](/organizations#in-your-app)

```ts
const { organization, activeTeamId, refresh } = useAuthActiveOrganization()
// organization.value: { id, name, slug, logo, members, invitations } | null
```

### `useAuthDeviceAccounts()`

The accounts signed in on this browser, with Better Auth's Multi Session plugin. Empty without it.
[More](/sign-in/multi-session)

```ts
const { accounts, switchTo, signOutOf, addAccountLink, refresh } = useAuthDeviceAccounts()
// accounts.value: Array<{ token, user: { id, name, email, image }, current }>
```

Switching to an account reloads the app, so every page's data is the new account's.

### `useAuthPages()`

Where the module's sign-in and account pages are, as set in `pages`. A page you turned off is `false`.

```ts
const pages = useAuthPages()
// { signIn: '/login', signUp: '/signup', account: '/account', … }
```

### `useAuthRedirectTarget()`

Where to go after signing in, as @nuxtjs/better-auth decides it: its `?redirect=`, else its
`redirects.authenticated`, else `/`. Only ever a path on your own site.

### `useAuthCapabilities()`

What your Better Auth set-up offers: the sign-in methods, providers and plugins that are on. Fetched once per page
load, during server rendering.

```ts
const { capabilities, loaded } = useAuthCapabilities()
if ((await loaded)?.passkey) {
  // …
}
```

### `useAuthI18n()`

The module's words, in the current language, with your own from `messages`. [More](/customization/languages)

```ts
const { t, locale, errorMessage } = useAuthI18n()
t('signIn.title')
// An error's words: translated by its code when there's a translation, else its own message.
errorMessage(error)
```

### `useBetterAuthAdminCan()`

Whether the signed-in user's role allows these [Better Auth Admin permissions](/admin/roles#permissions), checked
with the same roles as the server. Admin dashboard only.

```ts
const can = useBetterAuthAdminCan()
can({ user: ['ban'] })
```

### `useBetterAuthAdminPath()`

Turns a path into a URL under the admin route. Admin dashboard only.

```ts
const adminPath = useBetterAuthAdminPath()
adminPath('/users') // '/admin/users'
```

## Components

| Component | |
| --- | --- |
| `<AuthAccountSwitcher />` | The accounts signed in on this browser, to switch between, sign out of, or add to. Shows nothing without multi-session. [More](/sign-in/multi-session) |
| `<AuthOrganizationSwitcher />` | The active organization and team, to switch between. Only with `organization` on. [More](/organizations#in-your-app) |
| `<AdminImpersonationBanner />` | "You're signed in as …" while staff impersonate someone, with the way back. Only with the admin dashboard on. [More](/admin/users) |

The module's own pages use components prefixed `BetterAuthUi`, and composables prefixed `useBetterAuthAdmin` besides
the two above. They're not for your app and may change in any release.

## Page meta

`betterAuthAdmin` adds your own page under the admin route to the dashboard's sidebar and search:

```ts
definePageMeta({
  betterAuthAdmin: { label: 'Reports', icon: 'i-lucide-chart-bar', permissions: { user: ['list'] }, order: 0 }
})
```

## Server utilities

Auto-imported in your server routes, with the admin dashboard on. [More](/admin/extending#api-routes)

### `requireBetterAuthAdmin(event, permissions)`

Requires a signed-in user whose role has the Better Auth Admin permissions: a 401 when signed out, a 403 without
them. Returns the user, Better Auth's context and its instance.

```ts
const { user, context, auth } = await requireBetterAuthAdmin(event, { user: ['list'] })
```

### `recordBetterAuthAdminAction(event, context, entry)`

Adds an entry to the [audit log](/admin/audit-log), with the request's IP and browser. Does nothing with the audit log
off, and never throws.

```ts
await recordBetterAuthAdminAction(event, context, {
  action: 'report.export',
  actor: user,
  // Who it was done to, if anyone.
  target: null,
  details: { rows: 120 }
})
```

## Package entries

For files the module loads, and your Better Auth config.

### `@treygrr/nuxt-better-auth-ui/emails`

[More](/customization/emails)

| Export | |
| --- | --- |
| `defineBetterAuthEmailSender(send)` | Your function that delivers emails, for `emails.send`. |
| `defineBetterAuthEmail(name, render)` | A template for one email, for `emails.templates`. Returns HTML, or `{ subject, html, text }`. |

| `renderEmail(name, data, template?, locale?)` | Renders an email as the module would send it: your template, else the default in that language. |

## Hooks

The module adds Better Auth's plugins itself, so their function options go in files of yours, which it loads:

| Option | The file's default export |
| --- | --- |
| `emails.send` | Your email sender. [More](/customization/emails) |
| `emails.templates` | One template per email. [More](/customization/emails#your-own-templates) |
| `sms.send` | Your text sender. [More](/sign-in/phone-numbers) |
| `anonymous.onLinkAccount` | Better Auth's `onLinkAccount`, to move a guest's data to their new account. [More](/sign-in/methods#moving-a-guests-data) |
| `organization.serverOptions` | More of the Organization plugin's options, such as `organizationHooks`. [More](/organizations#options-that-are-functions) |
| `sso.serverOptions` | More of the SSO plugin's options, such as `getRole` for who joins as what. [More](/organizations/sso#who-joins-as-what) |

Better Auth's own hooks (`databaseHooks`, `hooks`) go in your Better Auth config, as usual.
